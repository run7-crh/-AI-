# 知识图谱交互与图例优化设计

- 日期：2026-09-22
- 状态：待用户复核
- 范围：前端知识图谱页面的交互流畅度、图例可见性和数据状态提示

## 1. 目标与成功标准

用户在知识图谱页面拖拽节点、滚轮缩放和平移时保持稳定响应；页面下方的五类颜色图例改为顶部可换行图例条，始终完整显示并可筛选；节点详情、相邻概念和一键提问行为保持不变。

成功标准：

1. 拖拽和缩放过程中不因 Vue 状态更新或 `setOption` 重复触发力导向重算。
2. 五个固定类别及其颜色在常见窗口宽度下都可见；点击类别只更新一次图谱数据。
3. 筛选后的边只连接当前可见节点，未知类别使用中性灰色，不再静默归入“基础架构”。
4. 当图谱产物关系数为 0 时，页面能明确提示数据状态，不改变后端数据。
5. 前端测试、类型检查、构建和 diff 检查通过。

## 2. 现状与约束

- 图谱使用 ECharts 5 `graph` + `force`，当前 `GraphView.vue` 使用内置底部 legend 和持续布局动画。
- 当前工作区的 `backend/data/kg.json` 实测为 71 个节点、0 条边，且节点类别全部为“基础架构”；本次只增加前端可见提示，不修改图谱构建产物。
- 必须保留节点点击、右侧概念卡片、相邻概念切换、向 Agent 提问、重建知识库和现有 API 契约。
- 只修改与图谱页面、图谱 option 构建器及其测试直接相关的文件。

## 3. 方案

### 3.1 顶部自定义图例

移除 ECharts 内置 legend，`GraphView.vue` 渲染固定类别列表和动态“其他”类别。每项包含颜色圆点、名称和可点击状态，使用 flex 换行保证五类颜色完整显示。类别状态只影响筛选，不参与拖拽事件处理。

### 3.2 稳定的图谱更新

`buildGraphOption` 接收可见类别集合，生成过滤后的节点和边；隐藏类别的节点不参与布局，相关边同步移除。`GraphView` 仅在初次加载、图例筛选和必要的尺寸变化时调用 `setOption`。力导向图关闭持续 `layoutAnimation`，保留一次性布局；ResizeObserver 使用 requestAnimationFrame 合并连续 resize。

### 3.3 类别和数据提示

定义类别颜色的统一解析函数：已知类别使用固定颜色，未知类别使用中性灰色并归入“其他”。页面状态栏继续展示概念和关系数量；关系数为 0 时显示轻量提示，引导用户检查知识库重建状态。

## 4. 数据流与交互

```text
GET /api/graph
  -> GraphView 保存原始 GraphData
  -> visibleCategories 计算当前筛选
  -> buildGraphOption(data, visibleCategories)
  -> ECharts 一次性更新节点、边和布局
  -> 拖拽/缩放只由 ECharts 处理，不改 Vue 筛选状态
```

点击节点仍只更新 `selected`；点击相邻概念仍切换卡片；点击“向 Agent 提问”仍跳转 `/chat?ask=...`。

## 5. 错误处理与边界

- 图谱未构建、加载失败和重建流程保持现有行为。
- 空类别、未知类别和无关系图谱不会导致 option 构建异常。
- 关闭所有类别时显示空画布和明确提示，可重新点击图例恢复。
- 页面卸载时继续释放 ResizeObserver 和 ECharts 实例。

## 6. 验证策略

- 扩展 `graphOption` 单测：类别过滤、未知类别颜色、“其他”类别、边过滤和五类图例数据。
- 运行前端 Vitest、`vue-tsc -b`、Vite build 和 `git diff --check`。
- 手动验收：初次加载、拖拽、滚轮缩放、图例换行、逐类筛选、全隐藏/恢复、节点详情和一键提问。

## 7. 非目标

- 不改后端知识图谱抽取、节点/边生成逻辑或 API。
- 不替换 ECharts 为 Canvas/SVG 自研渲染器。
- 不新增图数据库、GraphRAG 或图谱编辑能力。
